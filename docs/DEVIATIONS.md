# Deviations from HALoGEN

Every change we made to HALoGEN's released code at commit `8b7dd77e`. The code changes are in
`patches/halogen-p0-7.patch` and `patches/halogen-p1-8-openfactscore.patch`. Anything not listed
here is reproduced exactly, typos included.

Class labels: **forced** (an upstream dependency is gone), **chosen** (standardisation),
**fixed** (a known defect corrected), **new** (a defect we found).

## Generation settings

HALoGEN's paper states no generation settings. Its code sets them for one path only:
`verifiers/get_model_responses.py` calls GPT chat models with temperature 0 and `max_tokens=128`,
and calls every open model through Together with no settings, so those ran on Together's
defaults at the time, which are not recorded. We use 128 new tokens with no stop sequences and
HALoGEN's `prompt` verbatim, with no added template. Near their maximum length, 76–92% of the
released responses end mid-sentence, so HALoGEN's output was cut at a fixed token budget too
(`scripts/halogen_response_lengths.py`). The greedy pass (sample 0) uses temperature 0, as
HALoGEN's one configured path does; the five sampled passes use temperature 1.0 and top_p 0.9,
which do not come from HALoGEN, since HALoGEN generated once per prompt. Every generation's
settings and seed are in `data/generation_plan/`.

## Known non-reproducibility inherited from HALoGEN

- The paper's verifiers used Llama-2-70B on Together, which has since been deprecated.
- HALoGEN's own Scientific Attribution evaluator used an internal Semantic Scholar API. The
  public-API version in the repository flags more references as hallucinated.

## Why the verifier wrapper is not a patch

`hallutrace/verifier_runner.py` replaces `src/evaluate_hallucinations.py` rather than patching
it. Deviations 10 to 12 are defects in how that script and the verifiers are wired together,
not in how they verify. Patching them would mean rewriting the released entry point line by
line and then arguing that our version still matches the paper. Calling the same classes with
the same methods and the same prompts from our own code keeps the verification logic untouched
and leaves the released file as published for anyone comparing against it.

The wrapper adds nothing to the scoring. It normalises four things: one call signature for all
nine tasks, keys read from the environment rather than from `config.yml`, input columns checked
before any paid call, and an output that lands at the requested path or raises.
`python -m tests.test_verifier_runner` covers all of it without a key or a network call.
